Інтелектуальна система рекомендацій мультимедійного контенту. Ось як я бачу цю тему:

коли я придумував цю тему я придумав мультимедійну систему яка включає в себе музику, фільми та ігри. 
далі якщо я наприклад люблю ігри про гонки, мені рекомендує фільми про гонки, і музику яка підходить під цю гру. 
також є користувачі, заходячи на профіль LLM буде порівнювати смаки мої і того на чий профіль зайшов, і якщо наприклад я люблю рок, 
гри про гонки, і фільми про романтику, а він також само але замість року джаз, то мені буде це рекомендувати "Я схожий на тебе на 82%, 
але я люблю джаз замість року, може хочеш його також послухати" або щось таке. тобто цифру ми повинні давати LLM, а вона використовується як AI-summary. 
і виходить що на старті щоб почати це все рекомендувати як і користувачів так і все це, треба щоб користувач додав в список улюбленого те,
що йому подобається, певно це пошук по якимось тегам там обираючи декілька тегів і так далі.


1. Контентна фільтрація (в межах домену)
На основі тегів, жанрів і keywords айтемів які ти лайкнув — знаходимо інший контент з максимальним перетином. Лайкнув Elden Ring → система знаходить інші ігри з тегами Dark Fantasy, Atmospheric, Difficult.
2. Крос-доменна фільтрація (між доменами)
Будуємо єдиний смаковий профіль юзера по всіх трьох доменах → знаходимо контент в інших доменах що відповідає цьому профілю. Любиш гонки в іграх → рекомендуємо фільми з keyword car race і музику з тегом fast.
3. Соціальна фільтрація + LLM (між юзерами)
Заходячи на чийсь профіль — система рахує cosine similarity між вашими смаковими векторами → знаходить taste gap (що є у нього чого немає у тебе) → Claude генерує людський текст:
"Ви схожі на 79% — обидва любите атмосферні RPG і Sci-Fi, але він слухає джаз замість металу. Можливо варто спробувати?"
LLM тут не генерує рекомендацію — він пояснює те що порахував алгоритм.

Як це працює для юзера
1. Зайшов → бачить популярний контент
2. Лайкнув кілька айтемів → система починає рекомендувати
3. Чим більше лайків → точніший профіль → кращі рекомендації
4. Зайшов на профіль іншого юзера → Claude порівнює смаки

Абсолютно правильно. Це і є головна проблема крос-домену.

Чому пряма косинусна схожість не працює між доменами:


Elden Ring tags:    [Dark Fantasy, Atmospheric, Difficult, RPG]
The Green Knight:   [medieval, hero, quest, tragic hero]
Heilung (музика):   [folk, ambient, ritual]

→ Перетин = 0. Але контентно вони дуже схожі.
Рішення — sentence-transformers:
Модель (наприклад all-MiniLM-L6-v2) перетворює текст в числовий вектор де близькість за змістом = близькість у просторі, незалежно від точних слів.
"Dark Fantasy atmospheric difficult" → [0.2, 0.8, 0.1, ...]
"medieval quest tragic hero"        → [0.19, 0.77, 0.12, ...] ← близько!
"folk ambient ritual dark"          → [0.18, 0.75, 0.09, ...] ← теж близько!


Що обрали — і чи круто це
Стек:

Astro + React — нестандартний вибір для диплому, виглядає сучасно ✅
FastAPI — правильний вибір для ML/рекомендацій на Python ✅
PostgreSQL (Neon) — надійно, підтримує pgvector для embeddings ✅
Firebase Auth — швидко, безпечно, Google login з коробки ✅
Claude API — реальний LLM в продакшні, не "заглушка" ✅
Ідея:

Три домени + крос-домен — унікально серед студентських проектів ✅
LLM для пояснення рекомендацій — актуальна тема 2024-2025 ✅
Соціальне порівняння смаків — є академічне обґрунтування ✅
Проблеми і їх рішення
1. Мало даних — 100 айтемів на домен
Проблема: collaborative filtering не запрацює, content-based буде давати мало варіантів
Рішення: розширити до 300-500 через ті ж API. Один скрипт — пів дня роботи.

2. Різні словники між доменами
Проблема: теги ігор, keywords фільмів і теги музики — різні мови, пряме порівняння не працює
Рішення: sentence-transformers embeddings → єдиний семантичний простір. Вирішує проблему повністю.

3. Cold start — новий юзер без лайків
Проблема: немає від чого рекомендувати
Рішення: показуємо топ за рейтингом поки немає лайків. Після 2-3 лайків — контентна фільтрація вже працює. Прийнятно.

4. Мало реальних юзерів
Проблема: collaborative filtering потребує багато юзерів
Рішення: для диплому — робимо content-based + крос-домен як основу, collaborative згадуємо як перспективу. Чесно і академічно коректно.

5. Embeddings треба зберігати
Проблема: pgvector треба окремо налаштовувати в Neon
Рішення: Neon підтримує pgvector нативно, одна команда CREATE EXTENSION vector

Що реально складно
Тільки одне — крос-доменний міст через embeddings. Потрібно:

Встановити sentence-transformers (важка бібліотека)
Згенерувати вектори для всіх 300+ айтемів
Зберегти в pgvector
Написати запит nearest neighbor
Все інше — стандартні речі.
